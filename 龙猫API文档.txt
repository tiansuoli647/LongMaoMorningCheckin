加密流程:
1. 将请求 JSON 字符串转为字节数组（UTF-8 编码）
2. 从 assets/rsa_public_key.pem 加载 RSA 公钥
- 读取 PEM 文件，去除 -----BEGIN PUBLIC KEY----- 和 -----END PUBLIC KEY----- 标记
- 将 Base64 编码的公钥解码
- 使用 X509EncodedKeySpec 和 KeyFactory 生成 RSAPublicKey 对象
3. 初始化 Cipher 对象：Cipher.getInstance("RSA/ECB/PKCS1Padding")
4. 使用公钥初始化加密模式：cipher.init(Cipher.ENCRYPT_MODE, publicKey)
5. 分段加密（每段最大 117 字节）
- 对于每个数据段，调用 cipher.doFinal(bytes, offset, length)
- 将加密结果写入 ByteArrayOutputStream
6. 对完整的加密字节数组进行 Base64 编码（使用 android.util.Base64.encodeToString()）
7. 将 Base64 字符串作为请求体发送（Content-Type: application/json）
例外: sunRunExercisesDetail 端点不加密请求体，直接发送 JSON

1. 人脸识别图片处理
使用场景:

步骤3: 活体检测结果回调
@Override
protected void onActivityResult(int requestCode, int resultCode, Intent data) {
    if (requestCode == FACE_REQUEST_CODE) {
        if (resultCode == RESULT_OK) {
            // 检测成功，获取人脸图片路径
            String imagePath = data.getStringExtra("imagePath");
            boolean isSuccess = data.getBooleanExtra("isSuccess", false);

            if (isSuccess && imagePath != null) {
                // 转换为Base64
                String faceBase64 = Base64ImageUtil.imageToBase64(imagePath);
                // 继续提交流程
                submitWithFaceData(faceBase64);
            }
        } else {
            // 检测失败，提示用户重试
            Toast.makeText(this, "请完成人脸活体检测", Toast.LENGTH_SHORT).show();
        }
    }
}
Java
步骤4: 图片转Base64编码
工具类实现（g.o.c.h.c - Base64ImageUtil）：
public static String imageToBase64(String imagePath) throws Throwable {
    if (TextUtils.isEmpty(imagePath)) {
        return null;
    }

    FileInputStream fis = new FileInputStream(imagePath);
    byte[] bytes = new byte[fis.available()];
    fis.read(bytes);

    // 使用Android Base64编码，NO_WRAP表示不换行
    String base64 = Base64.encodeToString(bytes, Base64.NO_WRAP);
    fis.close();

    return base64;
}

编码选项: Base64.NO_WRAP（不换行）

图片格式: 百度人脸SDK返回的是JPEG格式图片
Base64识别: JPEG图片Base64编码后始终以 /9j/ 开头
编码选项: 必须使用 Base64.NO_WRAP 或等效选项，确保没有换行符
字符集: Base64字符串仅包含 A-Z, a-z, 0-9, +, / 和 = 字符

配速计算公式
配速（分钟/公里）= 总用时（秒）/ 60 / 里程（公里）
# Python 示例
def calculate_pace(used_time_seconds: int, km: float) -> str:
    """计算配速

    Args:
        used_time_seconds: 用时（秒）
        km: 里程（公里）

    Returns:
        配速字符串，格式如 "5'30''"
    """
    if km <= 0:
        return "--"

    pace_seconds = used_time_seconds / km  # 每公里秒数
    minutes = int(pace_seconds // 60)
    seconds = int(pace_seconds % 60)

    return f"{minutes}'{seconds:02d}''"

# 示例：1800秒跑3公里
print(calculate_pace(1800, 3.0))  # 输出: 10'00''
Python
热量消耗计算公式
消耗热量（千卡）≈ 里程（公里）× 67.34
# Python 示例
def calculate_calories(km: float) -> int:
    """计算消耗热量

    Args:
        km: 里程（公里）

    Returns:
        消耗热量（千卡）
    """
    return int(km * 67.34)

# 示例：跑3公里
print(calculate_calories(3.0))  # 输出: 202

认证机制
所有需要认证的接口都需要在请求体中包含 token 字段，该 token 通过登录接口获取。
关键业务流程
阳光跑完整流程
1. 登录获取 token
   POST /app/platform/login/login

2. 获取跑步任务（打卡点、要求等）
   POST /app/sunrun/getSunrunPaper

3. 开始跑步（记录开始状态）
   POST /app/sunrun/getRunBegin

4. 用户跑步（APP记录轨迹）

5. 提交跑步基础记录
   POST /app/platform/recrecord/sunRunExercises
   返回 scantronId

6. 提交跑步详情（轨迹+人脸）
   POST /app/platform/recrecord/sunRunExercisesDetail
   使用上一步的 scantronId
Plain text
微信登录完整流程
1. 初始化微信SDK并发起授权
   IWXAPI.sendReq(SendAuth.Req)
   scope: snsapi_userinfo

2. 微信APP回调返回授权码
   WXEntryActivity.onResp() -> code

3. 使用授权码获取服务器token
   POST /app/platform/serverlist/getLesseeServer
   Body: {"code": "微信授权码"}
   返回: token, path

4. 使用token执行登录
   POST /app/platform/login/login
   Body: {
     "loginWay": "1",
     "code": "微信授权码",
     "token": "服务器token",
     "longitude": "经度",
     "latitude": "纬度"
   }

5. 获取完整用户信息 LoginInfo
Plain text
早操签到流程
1. 登录获取 token
   POST /app/platform/login/login

2. 获取签到任务（签到点、时间等）
   POST /app/mornsign/getMornSignPaper

3. 用户到达签到点

4. 提交签到
   POST /app/platform/recrecord/morningExercises
Plain text
本地记录提交流程
1. 查询是否已有记录
   POST /app/sunrun/getSunrunArchLoacl

2. 如无记录，提交本地缓存的跑步数据
   POST /app/platform/recrecord/sunRunExercises
   （设置 ifLocalSubmit 和 LocalSubmitReason）
Plain text
安全注意事项
RSA 公钥暴露: 公钥存储在 APK 的 assets 目录，可被提取
无请求签名: 没有发现额外的请求签名机制
Token 验证: 主要依赖 token 进行身份验证
位置伪造风险: 经纬度由客户端提供，存在伪造可能
传感器数据: sensorString 字段可能包含防作弊数据
